Security is our highest concern: one week of security work on GoEasyERP

27 November 2026

A week ago we began a full security audit of GoEasyERP. We went through ten areas: logins and sessions, permissions, injection, the browser side, availability, data loss, secrets, infrastructure, the supply chain and our own process. We recorded more than 60 findings, each with a severity, and every one has since been fixed or deliberately decided on. Here is what changed:

  • Logins and sessions: stronger password rules, and users can change their own password. Sessions end after two hours without activity. Attempts to guess passwords are slowed down, and one person can't use that to lock others out. The very first administrator account can only be created with a setup token. The login page shows a user's companies only after the password is right.
  • Permissions: every API route is checked against the user's rights. A user without roles can do nothing, and only administrators manage users, roles and companies. Routines and reports now work on the record stored in the database, never on data sent by the browser. Users can change only their own preferences.
  • SQL injection: what users type, in filters, searches, sorting and report options, reaches the database only as data, never as part of a command. Field names are checked against the table, and company names are limited to safe characters.
  • Database safety: the application no longer runs as a database superuser. Deleting a company has to be confirmed by typing its name, and only an administrator can do it. Bulk deletes are logged, and demo data can never overwrite real data.
  • Browser protection: security headers on every response, protection against requests sent from other websites, and safe CSV exports.
  • Availability: limits on request rates, request sizes, database connections and concurrent jobs, so one user or one heavy request can't take the system down for everyone.
  • Secrets: the server refuses to start with a weak or missing secret or database password. Stored passwords for outside services are encrypted, and the keys can be rotated.
  • Audit trail: a change log shows who changed which field in the security and money tables. A security event log records logins, lockouts and refused actions, with e-mail alerts.
  • Extension apps: every extension app is automatically checked before it is built into the server. The check refuses code that could reach files, the network, secrets or the database outside the app's own records. It also scans the outside code an app brings in for known vulnerabilities.
  • Infrastructure: containers run as non-root, read-only and with minimal rights. TLS settings are tightened, and the toolchain is on the newest Go release, which still gets security fixes.
  • Supply chain and process: automated dependency and vulnerability scans in CI, build actions pinned to exact versions, and an automatic dependency update bot. A nightly security scan of the running application, an incident runbook, and a SECURITY.md that explains how to report a vulnerability.

Security isn't a one-off project. The audit findings and their fixes are now part of how we build GoEasyERP.
